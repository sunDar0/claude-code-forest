# 아키텍처 감사 — 속성·목적 정합 검증

코드를 바꾸지 않는다. **각 모듈이 자기 속성에 맞는 자리에 있는지**를 실측으로 판정하고, 어긋난 곳을 심각도와 함께 목록화한다. 교정은 refactor-surgeon 이 별도로 한다(이 스킬은 진단만).

## 왜 이렇게 하는가

기능 빌더 하네스는 "동작하는 산출물"만 본다. `renderer.js` 가 수천 줄 god-file 로 자라고 같은 함수가 여러 곳에 복제돼도 빌더는 문제로 인식하지 않는다 — 구조 정합은 빌더 책임 밖이라서다. 그래서 별도 감사가 필요하다. 감사의 가치는 **추측을 빼는 것** — "결합이 심할 것 같다"가 아니라 `grep -c` 수치로 올리고 내린다.

## 모듈 속성 분류 (1차 원리)

속성이 자리(계층)를 정한다. 각 소스 파일을 아래 중 하나로 판정한다.

| 속성 | 정의 | 마땅한 자리 |
|------|------|------------|
| **순수 데이터** | 상수·테이블만, 로직 0 | 공유 모듈(palette 등) |
| **순수 함수** | 입력→출력, 상태·IO·DOM 없음 | 도메인/유틸(seed·noise·activation·metrics) |
| **상태 보유** | 인스턴스 상태를 들고 변이 | 협력 객체(camera·state) |
| **IO/영속** | 파일·네트워크·DB | 데이터 레이어(server/store·aggregate) |
| **렌더** | 캔버스 그리기 | render/ 하위 |
| **UI/DOM** | DOM 조작·이벤트 배선 | ui·main·debug |
| **조율** | 위를 엮음 | renderer(잔존)·main.boot·server/index |

## 실측 원칙 — 추측 금지

결합도·복제·경계는 눈대중이 아니라 명령으로 잰다.

- **결합도**: `grep -c "this\.X"` 로 특정 상태에 몇 곳이 묶였는지. 함수 본문의 `this.` 스캔으로 자유 함수로 뗄 수 있는지 판정.
- **규칙 복제**: 같은 술어·상수가 서버·서버목·클라 몇 곳에 복제됐는지 grep 으로 실측(예: 자동 묶기 규칙, 목 CAP, 해시 함수).
- **god-file**: `wc -l` 로 현재 크기·메서드 수를 실제 확인해 보고(추정 크기 금지).
- 코드로 확정 못 하면 "확인 필요"로 그대로 표기. 단정하지 않는다.

## 의존 방향 검증

의존은 한 방향이어야 한다: **UI → 도메인 → 데이터**, 렌더는 상태를 변이하지 않는다. import 그래프를 그려 역방향·순환·경계 누수를 찾는다. 위반 신호: 프론트가 데이터 파일 직접 import, 서버 규칙이 클라에 복제, 렌더 함수가 상태를 쓰기.

## 목적 정합

모듈이 존재 이유(사용 목적)대로 구현됐는지 본다. 예: "비교 시험"이 실제로 그 경로를 덮는가(`test/render-smoke.test.js` 의 골든 픽스처가 무엇을 커버하는지 확인), "공유 모듈"이 정말 단일 소스인가(복제 잔존 여부).

## 과교정 경계 — 떼지 말아야 할 것도 판정한다

모든 걸 쪼개라는 게 아니다(§2 단순 우선). 떼어내도 분리가 안 되고 더 지저분해지는 것은 **"두는 게 맞음"**으로 명시 판정한다. 예: 상태가 25곳 이상 얽힌 오버뷰 스냅샷, `renderer ↔ main` 양방향 카메라 결합. 인자에 상태가 줄줄이 따라오면 자유 함수 추출은 오히려 손해다.

## 재감사 = baseline 대비 delta (핵심)

"다시 감사"·"재검증" 요청이면 산출물을 그대로 새로 쓰지 말고, 이전 `_workspace/40_arch_review.md` 를 baseline 으로 삼아 **RESOLVED / PERSIST / NEW** 로 정렬한다.

| 분류 | 정의 | 의미 |
|------|------|------|
| RESOLVED | 1차에 있었으나 사라짐 | 교정이 효과를 냈다 |
| PERSIST | 1차·2차 모두 있음 | 잔존 — 아직 안 됨 |
| NEW | 1차에 없다 2차에 등장 | 도입 시점 정정 필수(아래) |

NEW 를 "이번 작업이 만든 결함"으로 바로 귀속하면 거의 틀린다. `git blame <path>:<line>`, `git log --diff-filter=A -- <path>`, `git merge-base` 로 도입 시점을 정정한다 — 다수는 이전 회차 범위 축소로 안 봤던 **기존 부채**다. 산출물 상단에 "1차 대비 delta" 절을 둔다.

## 출력

`_workspace/40_arch_review.md`:

1. **모듈 속성 표** — 파일별 속성·현재 자리·정합(✅/⚠️/❌)
2. **의존 그래프** — 방향·순환·경계 누수
3. **불일치 목록** — 각 항목 `[심각도 High/Med/Low] 제목 — file:line — 위반 근거 / 목표 자리`
4. **목표 아키텍처** — 현 규모에 맞는 계층·경계(과한 추상화 금지)
5. **우선순위 교정안 Top N** — 영향도 vs 비용, 각 교정을 덮는 안전망 명시. 안전망 없는 교정은 "검증 방법 신설 필요"로 표기

교정안은 승인 게이트를 거친다 — 사용자가 확인한 항목만 refactor-surgeon 에게 넘어간다. grep/node 실행이 막히면 1회 재시도, 재실패 시 막힌 지점 보고하고 그 항목 누락 명시.
