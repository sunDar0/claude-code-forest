# UI 디자인·완성도 점검

UI 가 기획대로 보이고 배치됐는지 **실제 화면**으로 점검한다. 핵심 규율: **코드만 보지 말고 라이브 캡처로 본다.** 코드상 정상이어도 화면에선 겹치고 가리고 잘린다(예: 포트 숫자가 톱니에 가림 — 코드는 멀쩡, 화면은 깨짐).

## 왜 라이브인가

이 프로젝트는 절차적 캔버스 렌더 + DOM 오버레이다. 결함의 상당수는 **렌더 결과**에서만 드러난다: z-index 겹침, 절대배치 충돌, 레터박스와 HUD 간섭, 펄스/애니메이션, 모달 중첩. 헤드리스 픽셀 해시나 CSS 읽기로는 이걸 못 잡는다. 그래서 claude-in-chrome 캡처가 점검의 1차 근거다. 못 보면 "미확인" 으로 남기고 봤다고 적지 않는다.

## 기획 소스 (판정 기준)

- `_workspace/00_architecture.md`:
  - §3 게임 모델 — 활성/잠금 그리드, 그리드는 논리 단위(도드라진 선 금지·은은한 톤 차이).
  - §5 렌더 규칙 — 스타듀밸리식 정사각 탑다운(다이아 금지), 둥근 활엽수, 연속 풀밭(§5-3 디버그 격자선 금지), 밝고 채도 높은 팔레트(§5-5), HUD 패널(§5-6), 유지 규칙(§5-7).
  - §7 카메라 — HUD 는 화면 고정(카메라 무관), 줌/팬, 레터박스 관련.
- `_workspace/20_forest_game_report.md`: 최근 UI 사양(레터박스 16:9·하단 고정, 자동 심기 토글·인디케이터·금색 아웃라인, 빈 대지 흙 자국 등). **가장 최근 섹션이 현재 의도** — 옛 사양과 충돌하면 최신 우선.
- 기획에 없는 요소는 "미정의" 로 분류하고 사용자에게 확인할 거리로 남긴다(임의 판정 금지).

## 점검할 화면 상태

서버를 띄우고(아래) 각 상태를 캡처한다. 한 상태만 보면 다른 상태 결함을 놓친다.

| 상태 | 진입 |
|------|------|
| 일반(숲) | 기본 화면, 적당히 줌인 |
| 오버뷰 | 최대 줌아웃 |
| 드릴다운 | 묶인 숲 클릭 |
| 콜드 스타트 | `?cold=1` — 시작일 모달 |
| 심는 중 | 자동 심기 ON → 인디케이터+차단 오버레이 |
| HUD 접기 | 우상단 접기 토글(◥) |
| 모달 | 상세(셀 클릭)·업로드 설정(톱니) |
| 레터박스 | 창을 낮고 넓게 / 세로로 길게 → 좌우·상하 여백 |
| 세부 | 빈 대지 흙 자국, 마지막 활성 금색 아웃라인, 자동 심기 토글 위치, 미니맵, 포트 표시 |

각 상태에서 **요소 겹침·잘림·정렬·가독성·펄스**를 본다. 의심 영역은 zoom 캡처로 확대.

## 서버 띄우기 (debug 상태 필요)

- 실서버(`npm start`, 5178)는 `FOREST_DEBUG=0` 이면 `?cold=1`·`?mock=1` 이 무시된다(실데이터만). 콜드·목·모달 흐름을 보려면 debug 서버를 별도 포트로 띄운다:
  - `FOREST_DEBUG=1 PORT=5180 node server/index.js &` → `http://localhost:5180/?cold=1&debug=1` 또는 `?mock=1`.
  - 점검 끝나면 띄운 debug 서버는 종료(사용자 서버 5178 은 건드리지 않는다).
- 실데이터 상태(일반·오버뷰·HUD)는 5178 로도 본다.

## 판정 두 축 (분리해 기록)

1. **기획 부합**: 화면이 §3·§5·§7·최근 사양의 의도와 맞나. 이탈이면 "기획 §X 는 A 인데 화면은 B".
2. **시각 완성도**: 기획과 무관한 깨짐 — 겹침/가림(z-index·절대배치), 잘림(레터박스·경계), 정렬 어긋남, 가독성(대비·크기), 임시/placeholder 잔존, 펄스·애니메이션 과함.

심각도: 치명(기능 가림·읽기 불가) > 중(눈에 띄는 이탈·어색) > 경(미세). 기획 중요도와 곱해 우선순위.

## 출력

`_workspace/60_ui_review.md`: 상태별 발견 목록 {상태·영역·분류·심각도·근거(스크린샷/좌표)·기획 기준·교정 제안} + 우선순위 교정 목록. 부합 항목도 간단 기록(회귀 추적).

## 안티패턴

- CSS·코드만 읽고 "정상" 판정 → 화면 겹침/가림을 놓친다. 반드시 캡처.
- 한 화면만 보고 끝 → 모달·심는 중·접기·레터박스 상태 결함 누락.
- "어색하다" 만 적기 → 무엇이 무엇을 어떻게(가린다/잘린다/어긋난다) + 기획 기준 명시.
- 기획에 없는 걸 임의로 "틀렸다" → "미정의, 사용자 확인" 으로.
