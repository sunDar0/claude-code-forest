# spec 조각 → 통합 상세 기획문서 합성

목표: 흩어진 영역별 사실 조각을, 독자가 처음부터 끝까지 읽으면 시스템을 이해하는 **하나의 일관된 기획문서**로 만든다.

## 왜 이렇게 하는가

조각은 정확하지만 파편이다. 독자는 "데이터가 어디서 와서 어떻게 나무가 되고 화면에 그려지는가"라는 흐름을 원한다. writer 의 일은 사실을 다시 쓰는 게 아니라 **순서·맥락·접합**을 부여하는 것. 그래서 조각의 단정은 그대로 보존하고, 추정은 추정으로 남긴다(신뢰 보존).

## 문서 구조 원칙

1. **위에서 아래로 좁힌다.** 개요(무엇을·왜) → 아키텍처(영역 지도·데이터 흐름 1장) → 영역별 상세. 독자가 큰 그림을 먼저 잡고 세부로 내려간다.

2. **데이터 계약은 단일 출처.** 서버 API shape, 영속 파일 포맷, 클라 소비 형태는 **한 절에서만 정의**하고 다른 절은 참조한다. 같은 계약을 두 곳에 적으면 둘이 갈라진다(새 drift).

3. **데이터 흐름을 따라 절을 배치.** 집계 → 영속 → API → 클라 상태 → 메트릭 매핑 → 렌더 → UI → 배포. 시스템이 데이터를 처리하는 순서가 곧 읽기 순서.

4. **결론 먼저.** 각 절은 한 문단 요약으로 연다. 표·단계·근거는 그 뒤.

5. **근거는 핵심에만.** 비자명한 동작·계약·함정에만 file:line 을 남긴다. 모든 줄에 달면 잡음.

## 합성 절차

1. `_workspace/spec_chunks/*.md` 전부 + (있으면) `00_architecture.md` 를 읽는다.
2. 영역 경계(노출/의존)를 대조해 접합부를 찾는다 — 한 영역의 "노출"이 다른 영역의 "의존"과 맞는지.
3. 조각 간 충돌·중복을 표시한다. 중복은 단일 출처로 합치고, 충돌은 §미확정에 병기(삭제 금지).
4. 위 구조로 통합 문서를 쓴다.
5. 조각의 "추정·미확정"을 모아 마지막 절에 정리한다(코드로 확정 못 한 것·drift·후속).

## drift 처리

기존 문서와 코드가 다르면 **현재 코드 기준으로 단정**하되, 갈린 지점을 한 줄로 남긴다:
> "자동 묶기는 완주 무관 무조건(§55). 기존 00_architecture 의 '완주 검사 후 수동 묶기'는 폐기."

이렇게 해야 옛 문서를 본 독자가 혼동하지 않는다.

## 출력

오케스트레이터가 지정한 경로(기본 `agenTree-spec.md`, 프로젝트 루트)에 Write 한다. 문서 상단에 "현재 코드 역설계 기준 / 00_architecture.md 는 히스토리"를 명시한다.

## 하지 말 것

- 조각에 없는 사실 창작(추정이면 추정으로만).
- 코드 개선·리팩토링 제안(기획문서는 현재를 기술; 개선은 별도 하네스).
- 조각을 그대로 이어 붙이기(합성 = 재구조화, 복사 아님).
